# 0.9.1 릴리스 검증 기록

## 태그 전 검증

- 로컬 `cargo test`: 263개 통과. Tauri crate: 68개 통과, 기존 1개 ignored.
- desktop 87개, omp 확장 11개와 타입 검사 통과.
- 실제 0.9.1 `aam --shim claude ... -c` 실행으로 관리 기록 없는 기본 경로의 원본 실행과 원본 종료값 보존을 확인했다. 인증 환경변수(API key·base URL), 기본 프로필 auth helper, 비활성 기본 프로필 binding의 프로젝트 허용 목록 위반은 원본 실행 전에 차단했다. 오류에는 인증 값이 노출되지 않았다. native CLI는 격리된 모의 실행 파일이며 실제 공급자에 프롬프트를 전송한 검증은 아니다.
- 계정 배정·인증 경계와 트레이 geometry를 독립 정적 리뷰했고 출시 차단 결함이 남아 있지 않았다. 정적 리뷰를 실제 실행 검증으로 간주하지 않는다.

## 로컬 사전 설치 확인 (0.9.0)

- Mac·Windows의 앱·CLI·서비스가 0.9.0이며 `setup --check`는 `ready: true`, `serviceVersionMismatch: false`였다.
- Mac은 사용자가 요청한 기본 Claude 계정의 `maxConcurrency: 0`을 적용했고, 기존 실행을 유지한 채 새 관리 lease 배정·예약을 확인했다. 검증용 예약은 종료하고 실행되지 않은 검증용 이력만 정리했다.
- Windows 11 일반 사용자 설치에서 200% 배율(화면 2880×1800, 작업 영역 2880×1704)의 실제 트레이 팝오버를 열고 상세를 펼쳤다. 내용 증가 시 위치를 위로 다시 맞췄으며 footer가 작업 영역 안에 보였다. 혼합 DPI 다중 모니터 실기기 검증은 하지 않았다.
- 이 확인은 로컬 0.9.0 설치 검증이다. 아직 만들어지지 않은 0.9.1 서명 후보나 앱 안 업데이트의 성공으로 주장하지 않는다.

## 서명 후보와 공개 검증 결과

- main의 immutable annotated tag `v0.9.1`로 만든 draft의 파일·전역 서명, `SHA256SUMS`, updater manifest를 검증했다.
- 동일 archive/setup.exe를 Mac·Windows의 0.9.0 설치본에 적용해 앱·CLI·실행 서비스 0.9.1, ready true·mismatch false를 확인했다. Mac 계정 22개·기존 관리 세션 2개, Windows 계정 9개를 보존했고 Windows 트레이 상세 펼침·footer를 실제 확인했다.
- 두 OS 설치 검증을 통과한 동일 draft를 [v0.9.1](https://github.com/lapalai/ojak/releases/tag/v0.9.1)로 공개했다. 태그·산출물은 바꾸지 않았다.
- 이후 사용자가 보낸 사진의 `UPDATE_RECOVERY_REQUIRED`는 트레이가 아닌 이전 설치 복구 문제였다. 0.9.1에는 이 복구 결함이 있어 새 설치에는 0.9.2를 사용한다.
- 계획했던 0.8.0 GUI 업데이트를 수행했다고 주장하지 않는다. 최종 앱 안 업데이트 검증은 후속 공개 0.9.2에서 이전 공개 0.9.1 GUI로 두 OS 모두 완료했다. 직접 설치와 앱 안 업데이트의 실행 경로·권한·세션 보존 및 한계는 [0.9.2 검증 기록](0.9.2-verification.md)에 구분했다.

Apple Developer ID 공증과 Windows Authenticode는 없다. 업데이터 서명과 구분한다.
