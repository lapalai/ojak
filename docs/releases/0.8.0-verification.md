## macOS 검증 (25.6.0 arm64)

- **설치 및 프로세스**: 공개 tar 산출물을 `~/Applications/Ojak.app`에 반영. 실행 바이너리(aam `06ffdf...`, aam-service `e930d5...`, ai-account-manager `c4c2def...`) SHA-256 및 아카이브 트리 비교 결과 0 diff. 단일 실행 프로세스(aam-service PID 12552, ai-account-manager PID 11497) 확인.
- **서비스 및 진단**: `aam --version` 0.8.0, `aam status --json` 서비스 버전 0.8.0. `aam setup --check` 결과 `ready: true`, `service: true`, `serviceVersionMismatch: false`, `error: null`.
- **네이티브 UI (`orca computer`)**: 윈도우 타이틀 `Ojak`, 서비스 켜짐, "Ojak 0.8.0" 버튼, 설정 모달 버전 0.8.0, [업데이트 확인] 시 "최신 버전이에요." 안내 확인.
- **앱 안 업데이트(0.6.3 → 0.8.0) 격리 번들 실측**:
  - 프로덕션 `~/Applications/Ojak.app`은 사전에 이미 0.8.0으로 교체되어 있었으므로, 앱 안 업데이트 동작 검증을 위해 공개 0.6.3 아카이브(SHA-256 `d82cde...`)를 `/tmp/ojak-0.6.3-official/Ojak.app`에 별도 격리 추출.
  - 0.6.3 GUI에서 [설치하고 다시 시작] → [지금 업데이트] 실행.
  - 실행 대상 번들인 `/tmp/ojak-0.6.3-official/Ojak.app`의 3개 바이너리 및 `CFBundleVersion`이 0.8.0 공개 바이트로 in-place 치환됨을 실측 확인(트리 diff 0).
- **런타임 및 브릿지**:
  - 서비스 재시작 직후(1791793326) 단일 초 내에 원인 미확정(`causes=-`)의 `outcome=rejected` 6건 관측(소켓·레이트리밋 추정 배제). 1791793327 이후 브릿지 거절 0건.
  - `aam omp-bridge status --json` 기준 `bridge.blocks`는 빈 배열 `[]`(활성 차단 없음).

## Windows 검증 (Windows 11 x64, agus2)

- **앱 안 업데이트(0.6.3 → 0.8.0)**: 비관리자 일반 권한(Medium Mandatory Level, Task Scheduler `Interactive / Limited`)의 0.6.3 앱 UI에서 [설치하고 다시 시작] 클릭.
- **산출물 적용**: 업데이터가 `latest.json` endpoint를 통해 임시 폴더에 다운로드한 `Ojak-0.8.0-installer.exe` 해시가 공개 `Ojak_0.8.0_x64-setup.exe` 해시(`7e9fd9ef...`)와 일치.
- **업데이트 후 상태**: `C:\Users\agus2\AppData\Local\Ojak` 내 aam, aam-service, ai-account-manager가 0.8.0 해시로 교체. 실행 프로세스 aam-service(PID 35712), ai-account-manager(PID 31508) 단일 실행. `setup --check` ready=true, mismatch=false. 레지스트리 DisplayVersion 0.8.0.
- **데이터 보존**: 계정 9개 보존, 설정 및 SQLite DB(`state.sqlite3`, `local-usage.sqlite3`), 토큰 보존 확인.

## 한계와 주의사항

1. **절차 위반**: 공개 전 게이트 미준수 사실은 사후 런타임 성공으로 무효화되지 않음.
2. **Mac 프로덕션 앱 검증 한계**: Mac의 앱 안 업데이트는 격리된 구버전 임시 번들의 in-place 갱신으로 확인하였으며, 프로덕션 경로(`~/Applications/Ojak.app`)는 사전에 이미 0.8.0으로 교체된 상태였음.
3. **Windows 설치기 로그**: 앱 업데이터가 백그라운드에서 실행한 setup.exe의 종료 코드 및 상세 stdout 로그는 수집되지 않아 파일 해시 교체 및 런타임 상태로 적용을 확인함.
4. **런타임 관측 범위**: 브릿지 요청 라우팅 성공이 외부 LLM API의 개별 모델 응답 2xx 성공을 증명하지는 않음(Gemini 턴 중 일시적 upstream socket ECONNRESET 관측됨).
