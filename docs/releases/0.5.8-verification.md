## 이번에 드러난 점

- Windows 설치가 처음 세 번은 `INSTALLER_FILES_BUSY`로 안전하게 거절됐다(파일 변경 없음). 열려 있던 omp 세션의 `aam.exe omp-observer write`가 `aam.exe`를 잡고 있었다. 사용자 승인 뒤 그 omp를 종료하고 설치했다. 설치 안내에 "열려 있는 omp를 먼저 종료"를 넣어야 한다.
- 일반 권한 Task Scheduler로 실행한 `/S` 설치는 같은 이유로 실패한 것이며, 일반 권한 설치 자체의 실패는 아니다(별도 재확인 필요).

## 남은 검증

- 공개 후 **0.3.0 → 앱 안 업데이트** 경로를 두 OS에서 확인하지 않았다. 직접 설치 검증과 구분한다.
