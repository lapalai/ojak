# Ojak 사용 안내

[README로 돌아가기](README.ko.md) · [English](usage.md) · **한국어** · [Bahasa Indonesia](usage.id.md)

처음이라면 [다운로드와 시작하기](README.ko.md#다운로드)부터 진행하세요. 이 문서에서는 계정 배정, 선택 기능, 업데이트와 문제 해결을 다룹니다. Ojak은 초기 미리보기 버전이에요. 본인 계정만 사용하고 [고지](README.ko.md#고지)를 먼저 확인해 주세요.

## 계정 배정

Ojak은 메시지마다가 아니라 **새 관리 세션을 시작할 때** 계정을 고릅니다. 시작한 대화는 같은 계정을 유지해요. 남은 한도 외에도 로그인 상태, 사용량 정보가 얼마나 최근인지, 동시 실행 자리, 배정 설정을 함께 확인합니다. 공급자 쪽 사용량을 미리 예약해 두는 기능은 아니에요.

검증된 Claude 계정의 `maxConcurrency`는 0이면 **동시 실행 개수 제한 없음**, 1~32이면 해당 개수까지만 관리 대화를 허용합니다(기본 1, 현재는 `account.update` RPC로 설정). 개수 제한을 없애도 대화들이 같은 계정의 사용량 한도를 함께 쓰며, 한도 소진·로그인 문제·같은 대화의 중복 재개는 계속 막습니다.

터미널에 `NO_ELIGIBLE_ACCOUNT`와 함께 원본 CLI로 실행한다는 안내가 나오면, 그 실행은 **Ojak 관리 세션이 아니며** 관리 세션 목록에도 기록되지 않습니다. 이 동작은 연결된 `claude`·`codex` 명령에 적용되고, `aam run`은 관리할 수 없을 때 원본으로 넘기지 않아요. 인증 충돌이나 지원하지 않는 옵션을 조용히 무시하지도 않습니다.

원본 Claude로 시작한 대화는 같은 폴더에서 `claude -c` 또는 `claude --continue`로 이어 갈 수 있습니다. Ojak 관리 기록이 없는 기본 경로에서는 원본 Claude가 기본 프로필의 대화를 선택해요(`CONTINUE_UNMANAGED`). 프로젝트 경로 규칙·명시 계정·부모 관리 문맥이 있으면 이 예외를 쓰지 않습니다. 관리 기록이 있는 대화는 기존 계정을 유지하며, 실행 중이거나 연결이 불확실한 대화를 이 방식으로 우회하지 않습니다.

계정을 예약하지 않고 배정 이유만 확인하려면:

```sh
aam explain --tool claude
# Codex는 다음 명령을 쓰세요.
aam explain --tool codex
```

| 코드 | 뜻 |
|---|---|
| `QUOTA_EXHAUSTED` | 이 요청에 적용되는 한도를 다 썼어요. |
| `QUOTA_STALE` / `QUOTA_UNKNOWN` | 사용량이 오래됐거나 확인되지 않아 자동으로 고르지 않아요. 사용량을 새로고침하고 로그인을 확인하세요. |
| `CAPACITY_RESERVED` | 다른 세션이 실행 자리를 쓰고 있거나, 그 세션이 끝났는지 확인되지 않았어요. |
| `MODEL_LIMIT_GUARD` | 특정 모델의 한도가 소진됐어요. CLI가 모델을 정하는 요청에서는 경고이며, 그 모델을 직접 지정하면 계정이 제외될 수 있어요. |
| `RESERVE_DEPRIORITIZED` / `RESERVE_FALLBACK` | 안전 여유량 안쪽이에요. 여유 있는 다른 계정을 먼저 쓰되, 없다면 남은 한도를 사용할 수 있어요. 배정을 무조건 막는 조건이 아니라 우선순위 설명입니다. |

### 한도를 다 쓴 대화 이어가기

Ojak으로 실행한 Claude Code·Codex 대화형 터미널에서 공식 대화 기록에 명시적인 사용량 한도 소진이 기록되면, 기존 실행과 자손 프로세스의 종료·서비스의 예약 해제를 확인한 뒤 다른 계정에서 같은 대화를 자동으로 다시 열어요. `[Y/n]` 확인은 없습니다. 이미 거친 계정으로 돌아가지 않으며 한 번의 실행에서 최대 8회 전환합니다. 다른 계정이 없거나 종료·대화 기록을 확인할 수 없으면 멈추고 이유를 알려 드립니다.

비대화형 실행(`claude -p`, `codex exec` 등), 파이프, 중첩 세션, 기록을 남기지 않는 실행, 작업 폴더를 만드는 `--worktree`나 안전하게 다시 적용할 수 없는 옵션은 자동 전환하지 않습니다. 일반 429·네트워크 오류·사용자의 종료도 전환 사유가 아닙니다. CLI 버전이 한도 소진을 지원되는 구조화 기록으로 남기지 않으면 감지할 수 없습니다. 이때는 실행을 종료한 뒤 같은 프로젝트 폴더에서 직접 이어 주세요.

```sh
aam continue
```

로그인이 아니라 **대화 기록을 복사**합니다. 새 프로세스로 대화를 다시 여는 것이지, 실행 중인 CLI 안에서 끊김 없이 계정만 바꾸는 기능은 아니에요. 프롬프트 캐시를 다시 만들기 때문에 첫 요청은 토큰을 더 쓸 수 있어요. 해당 프로필을 대화형으로 처음 쓰면 Claude Code의 첫 실행 안내가 나올 수도 있습니다.

### 설정 공유 범위

계정 자격 증명은 공유하지 않아요. Mac에서는 `~/.claude`·`~/.codex`의 지원되는 확장 폴더를 관리 프로필에 연결하고 일부 설정을 복사합니다. Windows에서는 일부 설정만 복사하고 폴더는 연결하지 않아요. Windows에서도 모든 스킬·플러그인 폴더가 함께 쓰인다고 가정하지 마세요. 정확한 허용 목록은 [launcher 문서](domains/launcher.md)에 있어요.

### 인증 설정이 충돌할 때

`AUTH_OVERRIDE_CONFLICT`는 API 키, 별도 base URL, auth helper나 다른 옵션이 계정의 인증 방식을 바꿀 수 있다는 뜻이에요. Ojak은 설정을 몰래 고치지 않고 멈춥니다. 안내에 나온 설정을 확인하되 비밀 값은 이슈에 붙이지 마세요. 관리 명령을 통해 인증을 바꾸기보다 앱의 계정 연결 기능으로 로그인해 주세요.

## omp 연동

**선택 기능이며 기본으로 꺼져 있어요.** 사용량 화면과 Claude Code·Codex 관리 실행에는 브릿지가 꼭 필요하지 않습니다. 켜면 구독 자격 증명을 로컬 프록시로 중개하므로 공급자 약관과 충돌할 수 있어요. 먼저 [고지](README.ko.md#고지)를 읽어 주세요.

```sh
aam omp-broker connect && aam omp-bridge connect
```

사용할 수 있는 로그인에 맞춰 `ojak-*` 공급자를 등록합니다. **새 omp 세션**에서 `/model`로 `ojak-*` 모델을 고르세요. 원래 공급자로 보내는 요청에는 Ojak 계정 배정이 적용되지 않아요.

- **Claude·Codex:** Ojak에 등록한 공식 CLI 계정 또는 omp의 원래 공급자 로그인 중 하나를 씁니다. 같은 계정을 두 번 로그인할 필요는 없어요.
- **Gemini(Antigravity)·Grok·Z.AI:** omp의 원래 공급자 로그인을 씁니다.
- 나중에 추가한 계정은 보통 약 1분 안에 반영돼요.
- Claude는 원래 키체인이나 인증 파일을, Codex는 파일 기반 인증 프로필을 씁니다. 갱신은 공식 CLI가 맡아요. 다른 Codex 인증 저장소를 파일 저장 방식으로 자동 변경하지 않습니다.

구현 상세는 [브릿지 문서](domains/omp-bridge.md)를 확인해 주세요.

## 토큰 환산액과 실제 과금

토큰·비용 화면은 이 컴퓨터의 omp·Claude Code·Codex 기록을 읽어 오늘·이번 달·전체 기간을 보여 줍니다. API 요금 기준 환산액은 **구독 청구액도, 크레딧 잔액도, 지출 상한도 아니에요.** 가격을 모르는 모델은 따로 표시합니다. 첫 스캔은 창을 닫아도 뒤에서 이어질 수 있어요. 읽는 동안 나오는 캐릭터 그림은 사용량 그래프가 아닙니다.

선택 설정 두 개를 켜면 구독 한도를 다 쓴 뒤 **Codex 크레딧** 또는 **Claude 추가 사용량**이 있는 계정으로 새 작업을 보낼 수 있어요. 두 설정 모두 기본으로 꺼져 있습니다. 켜도 구독 한도가 남은 사용 가능한 계정이 먼저이며, 한도가 리셋되면 새 배정부터 구독 한도를 다시 쓸 수 있어요.

공급자가 요금을 청구할 수 있습니다. Ojak은 청구된 금액을 볼 수 없고, 이미 실행 중인 공식 CLI가 공급자 쪽에서 유료 사용량으로 넘어가는 것을 막을 수도 없어요. 원본 CLI 실행 전 확인창이 모든 과금을 막아 준다는 뜻은 아닙니다. 크레딧 잔액은 Codex가 알려 주는 범위에서만 지원하며, 크레딧·추가 사용량 경로는 실제 과금 계정에서 아직 확인하지 못했어요.

## 업데이트

**설정 → 정보 → 업데이트 확인**을 이용하세요. 업데이터 공개키가 설정된 빌드는 시작할 때와 24시간마다 확인하고 메뉴바·트레이 팝오버에도 배지를 보여 줘요. 키가 없는 빌드는 업데이트 화면을 표시하지 않습니다. 업데이터 서명은 Apple 공증이나 Windows 코드 서명과 별개예요.

**업데이트 전에는 작업을 마쳐 주세요.** 설치 과정에서 Ojak 서비스를 다시 시작하므로 omp 브릿지 세션이 잠깐 끊길 수 있어요. 관리 세션이나 최근 브릿지 요청이 있으면 앱에서 지금 업데이트할지 나중에 할지 고릅니다. Windows 설치기는 진행 중이거나 종료가 불확실한 관리 세션이 있으면 멈춥니다.

앱 안 업데이트가 안 되면 [Releases](https://github.com/lapalai/ojak/releases/latest)에서 새 DMG·setup.exe를 받으세요. 서명 키가 바뀌면 직접 설치가 필요할 수 있어요. 0.1.0 → 0.1.1이 그런 경우였습니다.

### 직접 다시 설치한 뒤

- **Mac:** `Ojak.app`만 바꾸면 실행 중인 서비스는 예전 버전일 수 있어요. 앱을 열고 버전 불일치 안내에서 **서비스 다시 시작**을 누르세요. 안전 재시작은 관리 세션이 진행 중이거나 종료가 불확실하면 멈추고, 최근 omp 사용이 있으면 경고해요. CLI에서는 `aam service restart`를 쓰고 `aam service status` 또는 `aam setup --check`의 `serviceVersionMismatch`로 확인할 수 있어요.
- **Windows:** 같은 일반 사용자로 setup.exe를 실행하세요. 세션 검사 → 앱 소유 서비스 종료 → 파일 교체·확인 뒤, 로그인 자동 실행으로 등록돼 있었다면 서비스를 다시 켭니다. Orca·omp는 먼저 종료하세요.

운영자가 Mac 서비스를 직접 재시작할 때는 `launchctl kickstart -k gui/$(id -u)/ai.aam.service` 다음에 `aam integration install`을 실행합니다. 이 방법은 안전 재시작과 달리 **관리 세션을 먼저 검사하지 않아요.**

## Windows 설치

관리자 권한으로 설치하거나 설치 파일을 실행하지 마세요. [이 저장소의 릴리스](https://github.com/lapalai/ojak/releases/latest)에서 받은 파일인지 확인해 주세요. 백신이 `aam.exe`·`aam-service.exe`를 격리하면 탐지 내용과 출처부터 확인하고, 필요한 경우에만 해당 파일의 예외를 검토하세요. 보호 기능을 통째로 끄지 마세요. 확신이 없으면 개인정보나 자격 증명 없이 탐지 내용을 제보해 주세요.

0.7.0부터 Ojak 실행 파일을 쓰는 프로그램이 남아 있으면(`INSTALLER_FILES_BUSY`), 화면이 있는 설치에서는 대상 `aam.exe`와 이를 실행한 앱의 이름·프로세스 ID를 보여 주고 동의를 받습니다. 종료 대상은 현재 사용자의 같은 로그인 세션에서 해당 설치본을 쓰는 `aam.exe`뿐입니다. 표시된 실행 주체(Orca·omp 등)는 닫지 않습니다.

1. **정상 종료.** 동의하면 설치 도우미가 해당 프로그램에 정상 종료를 요청한 뒤 업데이트를 이어 갑니다. 그 프로그램에서 실행 중인 모든 작업이 멈출 수 있고, 닫힌 프로그램은 자동으로 다시 열리지 않아요. 대화도 자동으로 복원되지 않습니다.
2. **강제 종료는 별도 선택.** 정상 종료로 닫히지 않을 때만 저장하지 않은 데이터나 실행 중인 작업을 잃을 수 있다는 두 번째 경고를 보여 줍니다. 그 경고에 동의하지 않으면 강제로 닫지 않아요.
3. **새 프로그램은 새 동의.** 설치 중 새 프로세스가 실행 파일을 잡으면 다시 묻고, 이전 동의는 이어지지 않아요. 계속 다시 실행되면 최대 세 차례까지만 묻고 안전하게 설치를 멈춥니다.
4. **취소하면 거기서 멈춥니다.** 취소(`INSTALLER_CLOSE_CANCELLED`)하면 더 이상 아무것도 닫지 않고 파일도 바꾸지 않아요. 이미 허용해서 닫힌 프로그램은 그대로 닫혀 있어요.
5. **조용한(`/S`) 설치는 프로그램을 닫지 않습니다.** 대신 `INSTALLER_FILES_BUSY`로 실패해요.

도우미가 닫지 못한 프로그램이 파일을 계속 잡고 있거나 다른 이유로 멈췄다면:

1. 진행 중인 Claude Code·Codex 작업을 마치고 보조 프로세스를 계속 실행하는 앱(Orca·omp 등)을 정상 종료하세요. 창만 닫으면 관측 프로그램이 남아 `aam.exe`를 잡고 있을 수 있어요.
2. 설치를 다시 실행하세요. 이 안전 검사에서 멈춘 경우에는 앱 파일을 아직 교체하지 않았습니다.
3. 설치 창의 자세히에 `installer recover`가 보이면 이전 설치가 중간에 끊겼을 수 있어요. Orca·omp를 끈 뒤 [이슈로 알려 주세요](https://github.com/lapalai/ojak/issues). DB 수정이나 강제 파일 교체로 해결하려 하지 마세요.

설치 창의 자세히와 `%TEMP%\Ojak-installer.log`를 확인하세요. 0.6.3부터 실패 단계(`stage`), 도우미 종료값(`exit`), 실제 오류 코드(`code`)를 기록합니다. 기존 버전의 일반 안내문만으로는 실행 중인 작업이 원인인지 알 수 없습니다. 로그를 공유하기 전에는 개인정보가 없는지 확인하고 가려 주세요.

- `SESSION_BUSY` / `INSTALLER_FILES_BUSY`: 진행 중인 작업을 마치고 Ojak을 쓰는 프로그램(주로 Orca·omp)을 정상 종료한 뒤 재시도하세요. 조용한 설치는 프로그램을 닫지 않습니다.
- `INSTALLER_CLOSE_CANCELLED`: 종료 확인을 취소했습니다. 더 이상 프로그램을 닫지 않았고 파일도 바꾸지 않았습니다.
- `OMP_CONFIG_FAILED`: 이전 omp 연결의 설정을 복원하지 못했습니다. omp 설치·실행 상태를 확인하세요. omp를 연결한 적 없는 설치본은 omp 없이 제거할 수 있습니다.
- `LEASE_STATE_UNKNOWN`: 서비스가 꺼져 있어 저장된 세션의 안전 상태를 확인하지 못했습니다. Ojak 서비스를 다시 시작한 뒤 작업 상태를 확인하세요. DB나 lease를 직접 지우지 마세요.
- `HELPER_RESULT_UNAVAILABLE`: 도우미가 오류 코드 파일을 남기지 못했습니다. `exit=error`는 실행 실패, `exit=timeout`은 nsExec 시간 초과입니다. 설치 창의 자세히와 백신 격리 기록을 확인하세요.

## 세션이 끝났는데 자리가 남아 있을 때

Ojak은 시간이 지났다는 이유만으로 실행 자리를 풀지 않아요. 세션 상태를 확인해 주세요.

- **`SUSPECT`:** 실행 결과나 생존 여부를 아직 확인하지 못했어요. 실행기가 살아 있으면 스스로 정리되는 경우가 많습니다.
- **`ORPHANED`:** 실행기가 종료를 보고하기 전에 관리 연결이 끊겼어요. 자손 프로세스가 남아 있을 수 있습니다.

일시정지된 `claude -p`나 `kill -9`로 강제 종료한 실행기 때문에 생길 수 있어요. 먼저 해당 작업을 정상 종료해 주세요. **macOS**에서는 다음 명령으로 일시정지 상태를 확인할 수 있어요. `STAT`의 `T`가 일시정지입니다.

```sh
ps -o pid,ppid,stat,command -ax | grep '[c]laude -p'
```

본인의 정지된 프로세스를 확인하고 종료하기로 결정한 뒤에만 `kill -TERM <pid> && kill -CONT <pid>`를 쓰세요. 다른 예시의 PID를 그대로 붙여 넣거나 관계없는 작업을 종료하지 마세요. `CONT`는 정지된 프로세스가 종료 신호를 처리하도록 다시 움직입니다. 실행기까지 사라졌다면 종료 보고가 빠질 수 있어요.

자손 기록이 있는 고아 세션은 기록된 자손과 원래 프로세스 그룹이 끝난 것을 확인하면 자리를 풀 수 있어요. 기록이 없으면 재부팅이 있어야 남은 프로세스가 없음을 확정할 수 있습니다. 재부팅 뒤 서비스가 시작되면 정리할 수 있어요. **자리를 풀려고 서비스 DB를 직접 고치지 마세요.** 다른 사용 가능한 계정으로는 배정이 계속됩니다.

## Mac 고급 설치

[install.sh](../install.sh)를 읽고, 새 작업 폴더에 내려받아 내용을 확인하세요.

```sh
curl -fsSL https://raw.githubusercontent.com/lapalai/ojak/main/install.sh -o install.sh
```

검토한 뒤 실행 계획을 확인하고 설치하세요.

```sh
sh install.sh --dry-run
sh install.sh
```

공개 릴리스를 선택하고 arm64 DMG를 `SHA256SUMS`와 대조한 뒤 `~/Applications/Ojak.app`에 설치해요. 기존 설치본은 안전한 서비스 종료 검사에 통과해야 교체하며, 관리 세션이 진행 중이거나 종료가 불확실하면 멈춥니다. 완료 여부는 `--status`가 아닌 `aam setup --check`로 확인해요. 체크섬은 Apple 공증이 아닙니다. 앱만 설치되고 설정이 끝나지 않은 상태는 준비 완료와 구분해 알려 줍니다.

| 옵션 | 동작 |
|---|---|
| `--version 0.5.8` | 최신 버전 대신 지정한 공개 릴리스를 설치해요. |
| `--dry-run` | 설치하거나 설정을 바꾸지 않고 실행 계획만 보여 줘요. |
| `--with-omp` | 이미 설치된 omp도 연결해요. 명시적으로 선택할 때만 실행하며 [연동 위험](#omp-연동)을 먼저 확인하세요. |
| `--system` | `/Applications`에 설치해요. 이 설치 방식에서만 sudo를 씁니다. |
| `--skip-service` | 신규 설치·같은 버전 재설정에서 서비스 설정을 건너뛰어요. 기존 앱 교체에는 안전한 서비스 종료가 필요하므로 이 옵션을 쓸 수 없어요. |
| `--skip-integration` | `aam integration install`을 건너뛰어요. |
| `--skip-shell` | `aam shell install`을 건너뛰어요. |
| `--clear-quarantine` | 명시적으로 선택했을 때 복사한 앱의 quarantine 속성을 지워요. 기본으로 꺼져 있고 공증을 대신하지 않아요. 일반 macOS 허용 절차를 권장합니다. |

앱의 시작하기 화면 대신 CLI로 서비스와 터미널 연결을 준비하려면 `aam setup`을 쓰세요. 자동 PATH 설정은 zsh용이며, 다른 셸은 시작하기 진단 안내를 따라 주세요.

## Windows 터미널 설치

[install.ps1](../install.ps1)를 읽고, 일반 사용자 PowerShell에서 새 작업 폴더에 내려받으세요.

```powershell
Invoke-WebRequest -UseBasicParsing https://raw.githubusercontent.com/lapalai/ojak/main/install.ps1 -OutFile install.ps1
```

내용을 검토한 뒤 실행하세요.

```powershell
.\install.ps1 -DryRun
.\install.ps1
```

공개 버전을 지정하려면 `-Version 0.5.8`, 기존 omp도 연결하려면 `-WithOmp`, 도움말은 `-Help`를 쓰세요. x64 설치 파일의 체크섬을 확인하고, 세션·파일 잠금 보호가 있는 기존 NSIS 설치기를 실행합니다. 업데이트 전에는 Orca·omp를 종료하세요. 설치를 진행하는 에이전트가 자기 세션을 강제로 종료해서는 안 됩니다. 스크립트 실행 정책에 막히면 보안 정책을 해제하지 말고 setup.exe 수동 설치를 이용하세요. 서명 없는 설치 파일에 대한 주의는 그대로 적용됩니다.

두 OS 모두 [공통 에이전트 안내](install-for-agents.md)로 설치를 맡길 수 있어요. 로그인 승인은 직접 해야 할 수 있습니다. `aam setup --status`는 명령 검사를 하지 않으니 `ready: true`가 될 때까지 반복해서 조회하지 마세요.


## 제거와 데이터 위치

**Mac:** `aam deactivate`로 Ojak이 추가한 연결을 되돌립니다. 앱까지 지우려면 저장소를 내려받은 폴더나 검토한 설치 스크립트가 있는 폴더에서 `sh install.sh --uninstall`을 실행하세요. `/Applications`에 설치했다면 `--uninstall --system`입니다.

**Windows:** **설정 → 앱 → Ojak → 제거**를 쓰세요. omp 연결을 되돌린 다음 서비스를 끕니다. 관리 작업이 실행 중이면 제거가 멈추므로 작업을 끝내거나 PC를 다시 시작한 뒤 재시도하세요. `aam deactivate`는 앱을 지우지 않고 연결만 되돌립니다.

제거해도 계정·프로필·로그는 남아요.

| 운영체제 | Ojak 데이터 폴더 |
|---|---|
| macOS | `~/Library/Application Support/AI Account Manager` |
| Windows | `%APPDATA%\AI Account Manager` |

SQLite 계정·배정 기록, `integration.json`, `ui-settings.json`, 로그 등이 들어 있어요. 자격 증명은 해당 공식 CLI의 인증 저장소나 프로필에 있으니 프로필 폴더를 공유하지 마세요. Ojak은 사용 통계를 전송하거나 진단 파일을 업로드하지 않습니다. 공급자 요청과 GitHub 업데이트 확인에는 네트워크를 써요. 자격 증명 처리와 비공개 제보는 [보안 정책](../SECURITY.md)을 참고해 주세요.
