# 연결 화면: 키별 크레딧 관리

## 확정한 정보 구조

사용자 확인: **API 키마다 만료일이 다르다.** 따라서 업체별 구역 안에서 각 키를 관리하며, 키별 금액·기간을 일반적인 공유 잔액 설정으로 취급하지 않는다.

- **연결 → API 키 → Anthropic → 해당 키의 ‘금액·기간’**이 입력·수정 위치다.
- 키 목록에는 이름·이번 달 추정 사용액과 별도로 만료일·남은 크레딧 추정액·상태를 표시한다. 시작 전인 키는 시작 시각도 표시한다.
- 상세 대화상자에서 금액·사용 시작·만료를 관리한다. 정확한 만료 입력을 기본으로 하며, 결제일 추정은 선택 사항이다.
- **배정 설정에는 사용 규칙만** 남긴다. 금액·기간 편집기를 두 곳에 중복으로 두지 않는다.
- OpenAI는 기존 유료 API 정책을 유지하며 Anthropic 크레딧 기간 입력을 표시하지 않는다.

## 보존해야 하는 데이터

새 입력은 선택한 키만 대상으로 한다. 이미 저장된 입력을 수정할 때는 같은 grant ID와 최초 예산을 이어 써 사용액이 초기화되거나 이중 차감되지 않게 한다. 다른 키의 기간을 가져오거나 덮어쓰지 않는다.

실제로 잔액을 공유하도록 **이미 묶여 있는 키**는 예외적으로 공유 표시·구성원·변경 영향 범위를 보여 준다. 자동으로 키별로 쪼개거나 사용액을 임의 배분하지 않는다. 공유 입력을 수정·삭제할 때는 영향을 확인하게 한다.

## 시각 방향

기존 Pretendard 글꼴과 밝은/어두운 테마 토큰을 유지한다. 업체명을 행마다 반복하지 않고 구역 제목으로 올린다. 키 식별자는 이름 아래 보조 정보로 낮추고, 만료·남은 크레딧은 해당 키의 바로 아래에 함께 둔다. 관리 작업은 ‘금액·기간’이라는 일관된 버튼으로 연다. 좁은 창에서는 사용액과 기간을 다음 줄에 배치한다.

## 기존 화면 관찰

2026-11-16, 실행 중인 Mac 설치본 Ojak 0.24.0의 연결 화면 상단과 API 키 목록을 캡처해 `ConnectionsView.tsx`, `ApiKeys.tsx`, `styles.css`, `ApiCreditGrantPanel.tsx`, `UsageView.tsx`와 대조했다.

- 업체가 섞인 한 목록에서 이름·업체 배지·긴 식별자·사용액·관리 버튼이 경쟁했고 버튼이 다음 줄로 꺾였다.
- 기존 시작·만료 입력은 사용 현황 → 배정 설정 → 직접 확인한 API 크레딧 안에 있어 키를 관리하는 곳에서 찾을 수 없었다.
- 정상 연결된 omp의 완료 단계 설명이 첫 화면 대부분을 차지했다.
- API 키 구역이 Claude Code와 Codex 사이에 있어 Claude 전용 기능으로 읽힐 수 있었다.

이번 작업은 **업체 구분 및 키별 금액·기간 관리**다. 정상 omp 요약 접기와 구독 계정/앱 연결/서비스 구역 재정렬은 별도 제안이며 이번 범위에 포함하지 않는다.

## 검증 범위 구분

화면 검증은 실제 React 컴포넌트에 예시 데이터와 격리 IPC를 넣어 수행한다. 이 결과는 네이티브 설치본·실제 Console 잔액·Windows 검증을 대신하지 않는다. 운영 키·정책·서비스는 변경하지 않는다.
